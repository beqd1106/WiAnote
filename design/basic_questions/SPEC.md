# WiAnote「基礎問題」作成仕様

## 目的
各レッスンの確認問題（マニュアルの細部を問う）がいきなりだと難しい、という利用者の声を受けて、
**確認問題の前に解く「基礎問題」を各レッスン10問**作る。
レッスン本文を一度読んだ初学者が **7〜9割解ける** 難易度にする。

## 難易度の基準（最重要）
- 問うのは「そのレッスンの柱となる概念・名前・役割」。細かい既定値・画面の項目名・ボタン位置は問わない（それは確認問題の役目）。
- 1問1論点。設問は短く（60字以内目安）、「〜とは何か」「〜するときに使うものはどれか」「〜の説明として正しいものはどれか」型を基本にする。
- 誤答は **明らかに別物だが無関係ではない** もの（同じレッスン内の別の機能・別の用語）にする。
  ひっかけ・部分的に正しい誤答・「〜のみ」「必ず」の揚げ足取りは使わない。
- 単一選択のみ（correctAnswers は要素1つ）。選択肢は必ず4つ。

## 事実の正確さ（必須）
- 典拠は **WinActor Ver.7.6 操作マニュアル** のテキスト `op_manual.txt`（`<<<PAGE N>>>` の N が出典ページ番号）。
- 各問題について必ず op_manual.txt を grep して根拠箇所を確認し、`source` に `"操作マニュアル p.N (見出し名)"` の形式で書く。
- レッスン本文だけにあり、マニュアルに根拠が無い一般論（RPAのクラス1〜3など）は、レッスン本文を根拠として
  `source` を `"レッスン本文（<レッスン名>）"` とする。**記憶で事実を足さない**。
- 版で変わる数（記録モードの数など）はマニュアル原文と完全一致させる。「Ver.7.5で追加」等のバージョン断定は書かない。

## 選択肢の「長さの癖」を作らない（必須）
- 4つの選択肢の字数をそろえる（最長と最短の差は目安で10字以内）。**正解が一番長くならないよう**意識する。
- 正解位置は 0/1/2/3 をレッスン内で均等に散らす（10問なら 3/3/2/2 程度）。
- 設問文に正解の語をそのまま含めない。

## 解説
- `explanation`：**「結論／それが何をするものか／混同しやすい隣との区別」の3点構成で100〜200字**。
- `wrongChoiceExplanations`：誤答3つそれぞれに、それが実際には何なのかを1文で（キーは "0"〜"3" の文字列、正解のキーは入れない）。
- `beginnerNote`：答えを書かずに着眼点を示す1文（ヒントに使われる。**正解の語を含めない**）。

## 既存問題との重複禁止
パケット末尾の既存問題と、設問＋正解が実質同じになる問題は作らない（同じ概念を、より基本的な角度から問うのはよい）。

## 出力形式
`out/<レッスンID>.json` に JSON 配列で書く。**3〜5問書くごとにファイルを上書き保存**すること（途中で止まっても成果が残るように）。

```json
{
  "id": "b-ov1-01",
  "question": "…",
  "choices": ["…","…","…","…"],
  "correctAnswers": [2],
  "explanation": "…",
  "wrongChoiceExplanations": {"0":"…","1":"…","3":"…"},
  "domain": "overview",
  "service": "<テーマ名。既存問題の [ ] 内の名前から最も近いものを使う>",
  "difficulty": 1,
  "tags": ["基礎", "<テーマ名>"],
  "source": "操作マニュアル p.13 (WinActor とは)",
  "beginnerNote": "…"
}
```
- id は `b-<レッスンIDの l- を除いた部分>-01`〜`-10`。domain はパケット冒頭の domain。
- 書き終えたら、自分で次を検算して報告：各問の選択肢字数（正解が単独最長の問題数）、正解位置の分布、解説の字数最小値。
